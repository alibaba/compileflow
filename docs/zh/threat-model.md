# 威胁模型

CompileFlow 的安全评估覆盖引擎、Deploy、Durable 和 Workbench，说明项目已经缓解的威胁、嵌入应用或部署环境负责的控制，以及仍需关注的风险。支持级别见[支持面清单](architecture/supported-surfaces.md)，具体配置和操作方法见[安全指南](security.md)。

## 1. 范围与信任边界

| 边界                            | 可信输入                                             | 权限与输出                                                                                                                    |
| ------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 引擎解析器与编译器              | 经过评审的 TBBPM/BPMN 定义和显式注册的扩展           | 生成的 Java 代码使用宿主 JVM 的进程、类路径、文件系统、网络和身份权限执行                                                     |
| Deploy 控制面与运行时           | 已认证的发布和路由命令                               | 不可变制品、别名、灰度状态和运行时选择                                                                                        |
| Durable 内核与存储              | 通过严格模式校验的流程定义、类型化值和应用提供的能力 | 持久化运行状态、调用上下文、租约、Effect、Wait 令牌摘要和 Outbox 记录；原始 Wait 令牌只会在受保护的 Outbox 投递过程中短暂存在 |
| Workbench 浏览器、网关与 Server | 来自可信边缘的已认证运维请求                         | 定义编辑、部署变更、执行、监控和数据库访问                                                                                    |
| 持续集成与发布                  | 已评审源码、固定依赖、受保护凭据和已授权版本标签     | JAR、源码包、SBOM、校验和与签名来源证明                                                                                       |

流程定义、Java Code、Java Action、脚本、Spring Bean、插件以及 Store/provider 实现都属于可信的可执行输入，CompileFlow 不提供沙箱隔离。认证、最终用户授权、租户策略、TLS 终止、数据库加固、备份和基础设施隔离由嵌入应用或部署环境负责。

## 2. 资产与参与者

需要保护的资产包括：流程定义和不可变制品摘要；部署别名和灰度状态；执行变量、Durable 快照、Effect 载荷、Wait 令牌和 Outbox 记录；数据库、API、签名和持续集成凭据；审计记录；以及带有 SBOM 和来源证明的发布制品。

相关参与者包括：

- 拥有仓库或签名权限的维护者和发布人员；
- 可信的流程作者和部署运维人员；
- 已认证的应用服务和 Workbench 网关身份；
- 嵌入应用、扩展、Effect 适配器、Store provider 和基础设施管理员；
- 未认证的网络客户端、恶意或已失陷的依赖，以及能够控制未评审定义、浏览器请求、数据库记录、制品投影存储或持续集成元数据的攻击者。

## 3. 主要数据流

1. 经过评审的定义通过类路径、应用内联输入、Deploy 或 Workbench 进入系统。引擎在编译和执行前完成有界解析、预检并生成准确的源码摘要。
2. 已认证的发布操作保存不可变版本，但不改变流量。路由调整通过独立的修订检查修改灰度状态；运行时将别名解析为确定版本，并在加载前校验内容身份。
3. Durable 命令在单个运行实例的权威事务中处理。Store 原子提交状态、Effect、Wait 事件、调用上下文和 Outbox 意图，租约与隔离令牌用于拒绝过期工作节点。
4. 浏览器只能通过可信边缘访问 Workbench Server。边缘会删除客户端传入的内部请求头，并加入服务端凭据；浏览器资源中不包含 Server API Key。
5. 持续集成使用固定工具和依赖清单构建已授权提交，发布制品的校验和与来源证明绑定到对应源码修订。

## 4. 威胁分析

| ID    | 威胁                                                                 | 项目控制                                                                                                                                              | 部署环境责任                                                                                              |
| ----- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| TM-01 | 不可信定义或扩展在宿主中执行任意代码                                 | 文档明确将定义视为可信代码；语义校验、严格类型、组件白名单和空 Java Code 编译类路径可减少意外暴露                                                     | 评审并授权定义；使用独立操作系统或容器隔离不可信代码；以最小权限运行宿主                                  |
| TM-02 | XXE、远程 Schema、路径穿越或超大定义泄露文件、耗尽资源               | XML 处理禁用 DTD、外部实体和外部 Schema；限制源码大小；类路径拒绝协议前缀、父目录跳转和已知网络 ClassLoader URL                                       | 约束自定义 ClassLoader 和制品解析器，并设置网络、内存限制                                                 |
| TM-03 | 客户端绕过 Workbench 认证或伪造内部身份                              | 生产配置缺少强 API Key 或服务身份时拒绝启动；凭据采用常量时间比较；只有健康检查允许匿名访问；随附网关会删除客户端凭据和转发请求头                     | 终止 TLS，认证并授权用户，删除不可信请求头，保护上游链路，轮换凭据，并按需提供用户级审计身份              |
| TM-04 | 已认证主体读取或修改其他租户的数据                                   | 命名空间和确定的流程身份可避免意外键冲突；变更 API 会记录已认证的服务身份                                                                             | 命名空间不等于授权；所有控制、执行和查询请求都必须执行租户策略，必要时使用数据库隔离                      |
| TM-05 | 制品被替换、过期路由被接受或回滚到错误代码                           | 不可变版本携带内容身份；发布和路由采用显式状态转换、乐观检查和确定目标；发布制品带有校验和与来源证明                                                  | 限制发布权限，保护制品传输和存储，检查灰度配置并监控对账失败                                              |
| TM-06 | 重试、崩溃或租约过期导致不可逆操作重复或完成状态丢失                 | Durable 使用稳定的运行、事件和执行序号，并通过事务状态转换、租约、隔离令牌、明确的 UNKNOWN Effect 状态和幂等 Outbox 契约控制重复执行                  | Effect provider 必须去重并核对 UNKNOWN 结果，认证 Outbox 消费方，并保留外部事务凭据                       |
| TM-07 | 变量、载荷、令牌、凭据或源码通过响应、日志、浏览器存储或构建输出泄露 | 错误契约不返回原始值；文档禁止记录敏感信息；Workbench 不接收浏览器端凭据配置；源码检查会拒绝生成物、本地制品和凭据                                    | 加密传输和存储，限制日志与备份，执行保留和脱敏策略，并通过密钥管理系统保存凭据                            |
| TM-08 | 高成本解析、编译、执行、队列或 API 调用造成拒绝服务                  | 流程定义大小、编译任务、工作线程池、队列、截止时间、租约批次和关闭过程均有明确上限并可观测                                                            | 在接入层配置请求限制、配额、准入控制、CPU 和内存限制，并进行容量规划和告警                                |
| TM-09 | 数据库失陷、结构漂移或数据丢失破坏控制面和 Durable 状态              | 事务、版本化数据库变更、结构校验、乐观并发、租约隔离和崩溃恢复测试用于保护应用不变量                                                                  | 使用最小权限数据库角色、加密连接和存储、限制管理权限、测试备份与时间点恢复，并监控数据库                  |
| TM-10 | 依赖、持续集成任务、基础镜像、Wrapper 或发布制品被替换               | 锁文件和依赖清单、带校验和的 Maven Wrapper、固定提交的 Action、固定摘要的镜像、依赖审查、CodeQL、SpotBugs、SBOM、校验和及制品来源证明共同保护构建链路 | 使用多因素认证和评审机制保护仓库设置与持续集成凭据；验证发布来源；评估镜像仓库、Runner 和构建服务的可信度 |
| TM-11 | 浏览器内容注入或边缘服务失陷后获得 Server 权限                       | 随附的 nginx 配置设置严格的 CSP 和安全请求头；React 不接收 Server 凭据；本地网关会清除敏感客户端请求头                                                | 评审自定义 HTML、渲染逻辑和网关策略，限制浏览器出站连接，不把 CORS 或 CSP 当作认证手段                    |

## 5. 风险管理

依赖清单按交付物划分：`compileflow-bom.json` 覆盖 Maven 库，`compileflow-workbench-server-bom.json` 覆盖 Workbench 后端，`compileflow-workbench-web-bom.json` 覆盖浏览器生产依赖。应用清单必须与 Server JAR 和一体化 JAR 的实际内容一致，包括内嵌依赖和 Spring Boot Loader。三份 SBOM 均随发布制品提供校验和与来源证明。

影响受支持能力面的未解决威胁必须明确负责人、影响、缓解措施和处理期限。确认不可利用的依赖漏洞应通过与对应 SBOM 关联的 CycloneDX VEX 文档记录，不能直接忽略。

安全边界发生重大变化或发布新的次要版本、主要版本时，应重新评估本模型。解析、可执行 Action、认证、路由权威、Durable 事务、持久化、持续集成凭据或发布身份发生变化时，还应同步更新安全指南和相关自动化测试。
